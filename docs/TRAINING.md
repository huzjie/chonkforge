# 为什么用 `skill` 做能力旋钮

本框架的训练演示用一个标量 `skill` 作为可训练能力参数，驱动三阶段的指标单调变化：

- **pretrain**：`loss = 1 - skill` 单调下降（代理下一 token 交叉熵）
- **sft**：多域 QA 准确率随 `skill` 上升
- **rl**：GRPO 组内相对优势 → reward 单调上升

**原因**：纯 Python 参考实现里跑真实梯度更新既不经济也难收敛；`skill` 把"能力"抽成一个可观测、可单调驱动的旋钮，让训练管线的**结构**（三阶段、奖励信号、指标曲线）先立起来。接真实模型时，把 `skill` 换成真实参数的梯度即可，管线不变。

**两条铁律**（反复踩坑）：`skill` 必须真正参与打分；训练 `delta` 恒正保证单调趋 1。
